## PR descriptions
A PR description never contains a test plan: the tests run in CI, and code that cannot be tested is not submitted, so a promise to test by hand is not a substitute. It holds three things. First, the increment the code adds, in a few lines. Second, a manual QA plan: what to open, run or click to see the increment working, as exact commands or steps. Third, a link to the live environment it deployed to, if any. When the change needs anything beyond merging to take effect or to be checked (a migration, a config or env change, a `tars pull`, a restart, a seed, a manual step on another system), list those as explicit extra steps with the exact commands, so nobody discovers them after the merge.
