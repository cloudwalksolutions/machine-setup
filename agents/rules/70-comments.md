## Comments
Comments are for users, not maintainers; tests are for maintainers. A comment explaining how or why code works is documentation nothing checks: it has to be maintained by hand, goes stale the moment the code moves, and then misleads. A test is executable and documents the key behavior for the use case, and it fails when it stops being true. So put intent in names and tests, and the why in the commit or PR, never in a comment that will rot. An ugly comment is one that compensates for a missing test or unreadable code: a header block saying what a file does, a line restating the name under it, a note in a test or config file. When you feel the urge to write one, rename the thing or add a spec instead.
